# Dual 完整融合模型与 pHoptNN 的结构置信度门控方案

日期：2026-09-24。状态：讨论稿；本轮仅核查代码、缓存及依赖并设计方案，未修改模型、结构缓存或运行训练。

## 1. 推荐决策

首版采用预测层融合：保留 Dual 完整预测器，单独训练 pHoptNN 原子图预测器，再用小容量、对结构置信度单调的门控融合两者。先保留独立运行环境，用有版本的数据文件交换预测；证明互补后再迁移核心代码。

首轮重点验证三个问题：pHoptNN 在相同 PHOPT 数据划分下是否有效；它是否能纠正 Dual 的部分错误；pLDDT 是否能预测这种相对优势。高 pLDDT 是结构可靠性的线索，不等于 pHopt 预测正确的概率。

## 2. 已核实的项目事实

- Dual 对应 `phgeofuse/dual_fusion.py` 与 `experiments/phgeofuse_redesign_20260914/dual_candidate_float64/`。当前完整输出为 0.5 × robust v1 + 0.5 × 双编码器专家，应使用返回值 `prediction`，不是内部 `dual_prediction`。
- robust v1 包含 PHGeoFuse，Dual 的检索也使用结构相关信息。两路融合并非纯序列与纯结构的完全独立对照，必须实测误差相关性。
- pHoptNN 位于 `/home/hetianci/projects/pHoptNN`。训练输入为原子级坐标、部分电荷、37 类原子名称编码及 5 维边特征。`l_max=-1` 时原始节点矩阵为 N×41；charge_power=2 后默认模型输入为 37×3=111 维，不能直接把 41 当作网络的 in_node_nf。
- Venus-DREAM 原始结构缓存含 9,774 个来源元数据文件：9,501 个 AlphaFold DB、273 个 ESMFold。主清单有 9,855 个样本记录，分别为 9,575 和 280；两种计数口径不同。
- 上一轮已用 P21673 验证 PDB→PQR/CIF→pHoptNN 构图：1,410 个节点、2,898 条有向边，节点特征 N×41、边特征 E×5，数值与索引检查通过。这不是完整训练验证。
- 本地保存的论文正文报告 EnzyBase12k 上 pHoptNN RMSE=0.588，EpHod=0.879，并进行了结构质量筛选。这不能直接证明优于当前 PHOPT 上的完整 Dual；也不能把对 EpHod 的比较扩展为已击败所有 PLM+检索模型。

## 3. 必须先处理的 pLDDT 量纲问题

对当前主清单做了只读统计：

| 来源 | 样本记录数 | mean_plddt 最小值 | 中位数 | 最大值 |
|---|---:|---:|---:|---:|
| AlphaFold DB | 9,575 | 30.2423 | 93.4113 | 98.7409 |
| ESMFold | 280 | 0.2990 | 0.8941 | 0.9756 |

ESMFold 原始 PDB 中也存在 B-factor=0.90 这样的值；当前 Hugging Face 导出代码把 0–1 的 pLDDT 直接写入 B-factor，而项目直接读取该数值。这意味着不能把这 280 条记录都当作低于 1/100 的低可信结构。

建立带版本的 `confidence_normalizer`：按结构来源、模型实现及明确记录的原始量纲，将这批 ESMFold pLDDT 乘 100，统一为 0–100；不能对所有未来文件仅凭数值小于 1 就自动乘 100。保留原始数值、归一化值、转换规则和源文件哈希。未知来源或量纲无法判定时返回质量状态，不伪造高置信度。若将来加入实验 PDB，实验 B-factor 不能直接解释为 pLDDT。

这已影响结构预处理：`foldseek_three_di()` 使用阈值 70，主清单中 280/280 条 ESMFold 样本的 3Di 字符串全部为 `#`；残基图还把 pLDDT 除以 100。需追踪对应 SaProt 缓存、残基图和下游 Dual 的依赖，评估实际预测影响。历史 Dual 包及结果作为固定对照；如修正其上游，另建版本并重算依赖缓存、模型及基线。不能只修改历史 PDB/特征后继续把旧权重结果视为原有同一版本。0–1 数值写入两位小数 PDB 时已损失部分精度，乘 100 可恢复正确量纲但不能恢复被舍入的小数信息。

新融合门控可以先使用单独归一化后的质量特征，同时明确其 Dual 专家仍是历史固定版本。

## 4. 首版融合模型

设 D(x) 为完整 Dual 预测，G(x) 为 pHoptNN 预测，两者均还原为原始 pH 单位：

`y_hat(x) = D(x) + w(x) * [G(x) - D(x)]`

其中 0≤w≤1。推荐先比较两个门控：

### A. 可解释规则基线

`w(x) = valid(x) * w_max * clip((q_mean(x) - t_low) / (t_high - t_low), 0, 1)`

`q_mean` 为按残基统计的平均 pLDDT；不要按重原子数加权。可用 t_low=50、t_high=90 作为预先规定的起始规则，w_max 从小型验证网格选取，包含 0。50/90 不是已验证的最优阈值，也不要求高 pLDDT 必须给 pHoptNN 100% 权重。

### B. 推荐主模型：低容量单调门控

`w(x) = valid(x) * w_max * sigmoid(b + softplus(a) * q_mean/100 - softplus(c) * f_lt70)`

`f_lt70` 是 pLDDT<70 的残基比例。固定其他输入时，平均 pLDDT 提高不会降低 pHoptNN 权重，低置信残基比例提高不会增加权重。只有少量参数，容易检查，也适合当前标签规模。让参数可收缩到接近常数，并保留 w=0 的完整 Dual 候选。是否采用门控由验证收益决定。

`valid=0` 仅用于结构不匹配、无法生成有效原子图或该样本 G 无有效输出等失败情形。需显式分支返回 D，避免计算 0×NaN。结构正常但质量低的样本由门控连续降权，首版不按 pLDDT 硬删样本。

训练目标：在合规的折外预测上最小化最终融合 MSE，加小幅参数正则化。推理时不输入标签、不以真实 pH 选择专家。首版不同时搜索大量损失、结构裁剪和复杂门控。

### 后续扩展及边界

- 候选质量信息：pLDDT 中位数、P10、低于 50/70 的比例、图覆盖率、结构来源、未知残基比例。先记录全部，仅少量进入首版门控。
- 验证 AFDB 与 ESMFold 在相同 pLDDT 下的误差是否一致；统一量纲不等于两者已校准。样本足够时增加来源偏置，避免用小样本拟合过多参数。
- 可进一步加入 Dual 检索支持强度、两路预测差值、多个种子的预测分歧。但分歧本身不说明谁正确，必须用折外数据学习；保持 pLDDT 的条件单调性。
- 酸碱可电离残基或已知活性位点附近的置信度可作为后续特征。全蛋白均值可能掩盖局部错误；注意力权重也不能直接当作可信度。
- pLDDT 不描述所有域间相对位置或化学环境误差。没有 PAE/pTM 时记录缺失，不杜撰。
- 暂不更改 GNN 的节点特征、消息权重或池化。把 pLDDT 引入 GNN 是第二阶段独立消融，可能要求重训且改变原模型兼容性。
- 新输入若连完整 Dual 所需结构都缺失，回退 G→D 也未必成立。需要另行准备明确的纯序列回退器，或报告无法完成完整预测。

## 5. 数据转换与图构建

1. 共用一份冻结 manifest，保存 sample_key、sequence_sha256、structure_sha256、split、cluster_id、原始来源和标签。样本键沿用项目已有约定并检查唯一性；不能只以 UniProt ID 联结。
2. 从原始 PDB 选择与目标序列对应的链；保留原始链、残基编号、插入码与图原子映射，避免合并链或给截断两端错误补肽键。
3. 使用 PDB2PQR 的固定 AMBER 配置补原子/氢并分配部分电荷，再提取重原子。训练和推理采用相同质子化规则；若指定 pH，必须为统一、预先规定的值，不能使用样本真实最适 pH。现有 PROPKA 残基 pKa 不是原子部分电荷的替代品。
4. PDB 转 CIF 供现有 RDKit 边特征流程使用。对齐 RDKit 与 PQR 的重原子标识；补原子、质子化残基别名和重排都可能破坏按数组下标的对应关系。无法对齐时使用明确记录的统一距离特征回退，不能悄悄把错位键特征赋给节点。
5. 对 X→A 代理位置保存掩码和零置信度，不把其化学特征当作真实已知残基。先记录影响，再决定额外过滤规则。
6. 首版保留完整有效链，采用现有原子图规则。若后续移除低置信残基，必须重建索引、键和链断裂，单独列为方法变体。论文中的结构筛选/裁剪规则不能被当作现有导出脚本已自动实现。
7. 图缓存与数据划分解耦，缓存原始标签或将标签单独存放；标签归一化、LDS 权重和其他学习统计只在各训练折拟合。

## 7. 训练与评估协议

### 快速可行性阶段

冻结历史 Dual 包；pHoptNN 在相同 PHOPT 训练样本上从头训练，先用 1 个种子验证能正常学习，再扩展到 3 个种子。现有官方权重先用于前向兼容测试；如用于监督预训练，必须先核查 EnzyBase12k 与 PHOPT 的训练/验证/测试序列重叠及同源关系。

在历史开发数据上查看 pLDDT 分箱后的两路误差、误差相关性与最佳固定混合权重，标记为探索性结果。复用已多次用于选择模型的验证集/测试集不能得到新的独立确认结论。

### 严格门控训练阶段

推荐同源分组的 5 折交叉拟合生成 OOF 预测，预算不足可先 3 折试运行。每个外层预测折的标签不能参与该折专家训练、早停、检索参考库或任何监督拟合。超参数和早停只能用外层训练部分的内部划分。

关键：需要完整 Dual 的 OOF 输出。当前包元数据已声明其嵌套评估只覆盖双编码器专家，未对完整 robust v1 融合做外层重训。不能只重训 ESM1v/ESM2 Ridge 或残差头、却复用见过预测折标签的 PHGeoFuse/检索组件。完整流程应逐折重建所有使用标签的基模型、参考库和内部残差训练；无标签结构、冻结 PLM 表征和图缓存可以跨折复用。

门控在 OOF 专家预测上拟合，门控结构及正则化由独立开发集选择；报告泛化分数使用外层嵌套评估或预先锁定的独立确认集。不要把训练门控所用的同一批 OOF 行上的拟合成绩称为融合模型的无偏测试分数。

正式部署可在全部开发训练数据重训专家，或使用折模型集成；选择在开发阶段固定，并检查其预测分布与门控训练时是否一致。测试集只用于最终冻结后的评估。历史 PHOPT 测试集多次被查看，后续报告应明确为 follow-up；若需要强确认结论，需要新的独立数据或预注册嵌套协议。

### 最小对照集合

1. 完整 Dual。
2. pHoptNN 单模型。
3. 验证选出的最佳固定权重融合。
4. pLDDT 规则门控。
5. pLDDT 单调学习门控。
6. 开发阶段的 oracle 选优上界，仅用于诊断互补潜力，绝不能用于部署或声称可实现成绩。

所有对照在相同样本集比较，同时报告全量覆盖率、PQR/图失败数和带回退的整体表现，避免只挑转换成功或高 pLDDT 的子集夸大收益。

主指标：RMSE；辅指标：MAE、Pearson、Spearman。按 pLDDT 的 <50、50–70、70–90、≥90 分层（记录样本量），按结构来源、低同源程度及 pH≤4、4<pH<10、pH≥10 分层。比较两路误差的相关性及门控增益；采用同源簇级配对 bootstrap 表达不确定性，跨种子报告均值和标准差。小分箱样本不足时不作强结论。

采用门控的条件：相对 Dual 和最佳固定融合存在稳定开发收益，低质量组没有不可接受退化，且收益不由来源、样本筛选或标签泄漏造成。若 pHoptNN 的相对误差与 pLDDT 无清晰关系，固定融合或接近零的结构权重也应保留为合理结果。

## 8. 跨运行环境的迁移方案

### 当前环境核查

| 依赖 | phbench | pHoptNN |
|---|---|---|
| Python | 3.10.20 | 3.10.21 |
| PyTorch | 2.0.0 | 2.5.1+cu121 |
| NumPy | 1.26.1 | 2.1.1 |
| scikit-learn | 1.2.2 | 1.7.2 |
| torch-geometric | 未安装 | 2.6.1 |
| scatter/sparse/cluster 扩展 | 未安装 | wheel 标记 pt24cu121 |
| Transformers | 4.40.0 | 未安装 |
| PDB2PQR / RDKit / e3nn | 未安装 | 3.6.1 / 2025.3.3 / 0.5.6 |

pHoptNN 的 torch=2.5.1 与扩展 wheel 标记 pt24 存在版本不匹配风险；上一轮构图成功并不代表所有扩展算子、GPU 前反向均通过。先核查实际使用的算子，保留当前环境作参照，在新环境选择相互匹配的 torch/CUDA/PyG wheel。不要直接执行未锁定 torch 版本、却固定 PyG wheel 系列的原安装脚本。

### 阶段 A：两个环境、统一产物接口（推荐首版）

- `phbench/bin/python` 运行完整 Dual，保留其 scikit-learn/joblib 加载环境。
- 经验证的 `pHoptNN` 独立环境运行 PQR/图构建及原子图训练/预测。
- 在 phbench 或轻量独立进程中运行融合门控。两个 Python 进程通过文件通信，不在一个进程导入两个环境。GPU 作业默认串行调度并在阶段结束释放显存。
- 每路输出 `sample_key, sequence_sha256, prediction, model_hash, fold_id, training_partition_hash, status`；结构路额外附上 `structure_sha256, graph_hash, quality_version`。质量表包含 mean/P10/f_lt70、来源及缺失掩码。
- 预测用 CSV/Parquet、质量及模型配置用 JSON、图用 NPZ 数值数组。路径用相对路径和可配置的数据根目录，便于复制到服务器；按 key 严格联结、拒绝重复/错配并保留失败状态，不能按文件行号拼接。
- 模型保存 `state_dict` 与完整结构配置、原子字典、charge_power、charge_scale、y_mean/y_std、图配置及代码版本。门控保存小型参数 JSON；无需交换整个 Python 数据集对象。

融合在数学上只需要两个预测和质量特征，不要求两个大型模型处于同一 Python 环境。

### 阶段 B：迁移核心代码

在融合收益明确后，将最小必要模型与构图代码放到例如 `phgeofuse/phoptnn_adapter/`，保留上游 MIT 版权及 commit，记录补丁。用相对导入解决 `models`、`utils`、`qm9` 与 Venus-DREAM 包名冲突；让 PDB2PQR 仍作为独立 CLI 工具，裁去未使用的可选分析依赖。

选择统一的 torch/CUDA/PyG 组合，在新环境重建而非就地覆盖 phbench。现有 Dual joblib 应继续在原兼容环境运行，或从同一训练数据在新版本重训/转换并做预测一致性验证；不能默认 scikit-learn 1.2.2 的对象在 1.7.2 无损加载。对保存的图/权重校验哈希，并在固定样本上检查图、前向预测及数值容差。单环境部署是后续工程选项，不是首版实验的前置条件。
